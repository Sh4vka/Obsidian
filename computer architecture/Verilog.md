## Module
Основной единицей описания устройств на Verilog является модуль. Как правило для каждого модуля создаётся отдельный файл с расширением “.v”.

Имя каждого модуля должно быть уникальным. К любым именам в языке Verilog предъявляются следующие требования:
1. В качестве имен нельзя использовать ключевые слова (можно только как
часть составного имени). Пример: z_input.
2. Имена могут состоять из латинских букв, цифр, «$», «_», например,
we_$in.
3. Цифры и «$» не могут стоять на первом месте в имени.

Входные и выходные порты позволяют подавать сигналы на вход проектируемой схемы, а также считывать значение с выхода схемы. Это необходимо, поскольку ни один модуль не может быть оторван от набора контактов реальной схемы, на которую модуль будет помещён (или же, в контексте симулирования работы схемы, от генераторов последовательностeй симулятора, а также модели устройства для фиксации выходного значения).

```verilog
module <имя_модуля> (список портов входных, выходных портов);
[набор локальных цепей и регистров]
набор конструкций, которые будут синтезироваться
endmodule
```

**input** служит для определения входных портов, 
**output** — для выходных портов,
**inout** — для двунаправленных.

### Module instantion
Чтобы использовать ряд модулей внутри другого модуля, потребуется создать необходимое число инстансов (экземпляров) соответствующих модулей. Для этих целей следует использовать синтаксис создания экземпляров модулей. Стоит отметить, что это один из возможных вариантов синтаксисов, однако рекомендуется использовать именно его из-за простоты самопроверки при подключении.

```verilog
<имя модуля> <имя экземпляра модуля> (
.<имя порта1>(<имя того, что подключается к порту1>),
.<имя порта2>(<имя того, что подключается к порту2>),
…);
```

### Переменные и цепи
Среди множества типов данных, используемых в Verilog HDL, отдельного внимания на данном этапе заслуживают цепи и переменные. Основные отличия между этими типами проявляются при моделировании работы устройства.

Цепи изменяют свое значение всякий раз, когда изменяются сигналы, от которых цепь зависит. Основная цепь, используемая для соединения между узлами, ассоциируется с ключевым словом «wire».

Переменные обновляют своё значение только внутри особых блоков.  Основной тип переменных ассоциируется с ключевым словом «reg». 

Как цепи, так и переменные могут иметь произвольную разрядность. Соответственно, их можно объявить, как векторы.

```verilog 
reg [A:B] <имя_1>, <имя_2>…;
wire [A:B] <имя_1>, <имя_2>…;
```
Под A в данном случае подразумевается старший (значимый) бит, под B — младший бит. Например, reg[3:0] in; — четырёхбитный регистр, старший разряд имеет номер 3; wire[0:5] q; — шестибитная цепь. Старший разряд имеет номер 0.

### Оператор assign
Для описания комбинационной логики используется оператор assign — оператор непрерывного присваивания. Например, код описывает «с» как провод, соединённый с выходом конъюнкции входных сигналов «а» и «b».

```verilog
input a,b;
wire c;
assign c = a & b;
```

### Логические уровни и способы задания значений
Для каждого бита цепи или переменной существует четыре возможных
логических уровня:
- 0 — логический ноль;
- 1 — логическая единица;
- X — неизвестное значение;
- Z — высокий импеданс.
Чтобы задать многоразрядное значение следует использовать следующий
синтаксис
```verilog
[разрядность] ’ [s] [основание] <значение>
```

Разрядность — число бит для записи числа. Указывается в десятичной системе счисления. «s» — необязательный параметр, указывает на то, что число является знаковым. Основание — основание системы счисления, в которой указывается значение. Возможные варианты:
- b — двоичная;
- o — восьмиричная;
- d — десятичная (по умолчанию);
- h — шестнадцатиричная.

Например, 8’b11110000 — двоичное восьмиразрядное число.
Стоит обратить внимание, что число автоматически дополняется, если разрядность больше, чем разрядов реально указано. Например, 6’b1101 будет дополнено до числа 0011012. Также, число автоматически усекается, если разрядность больше, чем разрядов реально указано. Например, 6’b0111101 будет усечено до числа 1111012.

Работа с переменными ведётся в процедурных блоках, к которым в первую
очередь относятся блоки «always» и «initial».

### Блок initial
Блок «initial» используется для того, чтобы задать значения переменных перед началом процесса симуляции. Если не производить такое задание значений, то по умолчанию все цепи будут проинициализированы значением высокого импеданса, а все переменные сброшены в ноль. Разумеется, начальное значение можно присвоить только переменным.
```verilog 
initial
begin [: <Имя_блока>]
<Набор операторов>;
end
```

### Блок always
Блок «always» относится к множеству поведенческих блоков.
```verilog
always [<список чуствительности>]
begin [: <имя блока>]
<набор операторов>;
end
```

Блок выполняет процесс **всегда**, когда переменная из списка чувствительности меняет своё значение или происходит какое-то событие.

```verilog
@ (<event_1> , <event_2> , …<event_n>)
```

Также имеет смысл обратить внимание на применение в качестве списка чувствительности символа «*» (@*). Такой синтаксис используется, чтобы указать в списке чувствительности все переменные, используемые в блоке «always» в правой части выражений (т.е. переменные, от которых зависит результат вычислений в блоке). Пример для блока «always» приведён ниже. При изменении значений хотя бы одной из переменных «а», «b», «c» будет произведена повторная обработка соответствующей конструкции.
```verilog
always @ (a, b, c)
begin
	d = a & b | c;
end
```
Блоки «always» зачастую применяют в случае, если требуется получить триггер в результате синтеза. Поэтому для описания событий могут быть применены два ключевых слова: «posedge» и «negedge». «posedge» — событие изменения уровня сигнала: 0 → 1, 0 → x, 0 → z, x → 1, z → 1. «negedge» — событие изменения уровня сигнала: 1 → 0, 1 → x, 1 → z, x → 0, z → 0. Пример для блока «always» с ключевым словом «posedge» приведён в листинге 3.11. При приходе переднего фронта сигнала «clk» будет произведен перерасчёт значения переменной «d».
Пример блока always, управляемого событием прихода переднего фронта на линии clk
```verilog
always @ (posedge clk)
	begin
		d = a & b | c;
	end
```

### Директива timescale
Для симуляции работы созданного описания схемы необходимо указывать временные задержки симуляции распространения сигнала. Для обозначения задержки используется символ «#». Единица измерения задержки соответствует значению, указанному при помощи «timescale». «timescale» — директива, использующаяся для установки временных единиц. При этом необязательно указывать соответствующую директиву для каждого модуля. Достаточно это сделать для модуля верхнего уровня. «time_unit» — используется для указания измерения задержек и времени симуляции, «time_precision» — указывает как значения задержки округляются перед использованием в симуляции.
```verilog
`timescale <time_unit>/<time_precision>
```

Поддерживаются следующие единицы измерения:
- fs — фемтосекунда;
- ps — пикосекунда;
- ns — наносекунда;
- us — микросекунда;
- ms — миллисекунда;
- s — секунда.

Пример указания временных единиц и задержки. Время задержек измеряется в миллисекундах с точностью до микросекунды, а значение на «i» через двадцать миллисекунд изменится на противоположное.
``` verilog
`timescale 1 ms/1 us
…
#20 i = ~i;
```

Следует обратить особое внимание на то, что временные задержки играют роль только в процессе моделирования и используются для того, чтобы получить модель событий в реальном устройстве. Для процессов, связанных с непосредственным переносом на ПЛИС, данные задержки не имеют смысла.

### Системные директивы
Последнее, что потребуется для выполнения практической работы — ряд системных директив. Они позволяют выполнить моделирование и провести контроль и анализ его результатов. 
К системным директивам относятся директивы вывода результатов моделирования и директивы окончания моделирования. $finish, $stop — директивы завершения моделирования. 
Директива $finish завершает моделирование и передаёт управление операционной системе. Директива $stop завершает моделирование и переводит систему в интерактивный режим. 
$display, $write — директивы для вывода в консоль значений.
